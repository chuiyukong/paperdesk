# PaperDesk 全流程体验审查与改进

检查日期：2026-10-20。基线版本：v1.3.0；本次实现：v1.4.0。

## 现有项目与约束

项目为原生 HTML、CSS、JavaScript 页面，Python 3.12 标准库 HTTP 服务，SQLite schema v4。三个主页面为论文总览、期刊管理、数据与备份；新建、编辑和详情复用侧栏，重要操作使用确认框。已有令牌与来源检查、保存回执、并发修改保护、旧数据升级和独立数据目录。

现有规范位于 README、使用说明和功能验证文档，没有独立 DESIGN.md。已增加项目根目录 DESIGN.md，保存选定 Linear 原始规范、MIT 许可和固定提交来源。采用组件层次、边线与节奏，不复制营销结构或专有字体。中文浅色工作区、最小 16px 与六种状态含义继续保留。

## 实际使用全流程及边界

| 环节 | 典型情况与边界 | 本次处理 |
| --- | --- | --- |
| 启动与升级 | 双击、重复启动、端口占用、旧页面与新服务混用 | 继续核对版本和数据身份；新增应用版本标记，同 schema 升级也备份，重复启动不备份 |
| 新建论文 | 从不同阶段进入、默认作者、唯一编号、空标题、重复编号 | 原规则保留；错误就近显示，分组帮助识别必填与阶段信息 |
| 直接添加旧投稿 | 已投稿/退修时填写实际期刊和原日期；无效日期不得留下半篇记录 | 字段和事务保持；当前投稿单独分组，等待天数仍按原日期计算 |
| 写作与计划 | 起始日期可空、初始目标期刊可空、目标不同于转投候选 | 清楚分组与说明；早期阶段隐藏转投空列，日期和用时不重复 |
| 查找记录 | 编号、标题、作者、标签、旧期刊稿号、阶段、期刊和超期筛选 | 保留搜索排序；显示当前筛选与清除入口，避免空结果被误解为数据消失 |
| 登记与修改投稿 | 一篇最多一个进行中轮次、退修仍持续计时、补录历史 | 保留所有规则；按投稿信息、进展结果、转投安排、备注分组 |
| 实际转投 | 结束旧轮次并新增一轮；无候选、曾投同刊、日期异常、保存失败 | 规则与事务不改；上一轮和新轮次视觉分组，详情标明轮次及当前/结束 |
| 录用、退稿与归档 | 结果影响阶段、旧备注不能误改阶段、归档保留历史 | 保留现有结果同步选项与提醒停止规则；本次不重新定义业务 |
| 期刊管理 | 投稿系统和投稿须知不同、URL 可空、协议错误、被引用期刊不能删除 | 期刊信息与两个链接分组；协议错误输入后清除，引用保护不变 |
| 本地稿件 | 多个文件、文件夹、手动路径、原文件移动、选择窗口取消 | 增加选择并关联入口和手动路径入口；继续只保存路径；防止选择结果写入已切换的侧栏 |
| 保存与异常 | 保存中、刷新失败、响应丢失、跨页面冲突、断连 | 原保存回执和冲突保护不变；保存中反馈、持续错误提示和重新读取入口更清楚 |
| 删除与恢复 | 删除论文/轮次、空备份、损坏备份、恢复写入失败 | 确认与恢复前数量预览不变；依用户明确选择取消操作前自动备份，文案明确实际影响 |
| 备份管理 | 新增、升级、普通编辑、手动备份、0/4/5/多份备份 | 新增和升级才自动备份；普通操作不生成；大于 4 份显示最新 3 份，其他展开查看 |
| 退出与重开 | 关闭标签仍有服务、退出服务、数据保存位置 | 原行为保持；导航与退出按钮在窄屏保持可用 |

## 发现的问题与已实现改进

| 编号 | 影响使用的问题 | 处理 |
| --- | --- | --- |
| UX-01 | 卡片、导航与头部过高，小窗口难以迅速看到论文 | 压缩卡片与头部，窄屏精简导航并保持置顶；保留可见退出按钮 |
| UX-02 | 表单依靠长串字段和少量标题，信息层级不清 | 使用语义 fieldset/legend 分组；不更改字段 ID、必填条件或数据结构 |
| UX-03 | 文件关联要先加空行再选文件，易误解为上传 | 增加一步选择并关联、保留手工路径，明确本地路径语义 |
| UX-04 | 浏览器默认错误气泡短暂、远离相关上下文 | 必填和链接格式错误就近显示；纠正时移除对应提示；全局错误可手动关闭 |
| UX-05 | 每次编辑及每次启动均刷新完整快照，备份列表占满页面 | 仅新增和升级自动生成；备份原因、最近保存与最近备份分别展示，历史备份折叠 |
| UX-06 | 渐变光斑和多层投影较多，状态与操作层次相近 | 采用石墨导航、钴蓝操作、纸白表面和细边线；六阶段仍有独立语义色 |
| UX-07 | 有筛选时仍容易把结果数量当作全部记录 | 增加筛选摘要与清除入口，保留总数与结果数 |
| UX-08 | 投稿记录缺少明确轮次序号 | 显示“第 N 轮 · 当前投稿/已结束”，保留原倒序与全部历史 |
| UX-09 | 原删除/恢复文案承诺自动备份，与新偏好不符 | 按实际策略改文案；提醒需要保留当前状态时可先导出，不增加新的审批步骤 |
| UX-10 | 异步文件选择或快速建期刊返回时，侧栏可能已切换 | 核对侧栏代次；已经保存的期刊仍保留，不把返回值误写入另一个表单 |

## 单独列出的投稿规则建议：本次不实施

1. **退修期间的等待归属。** 当前等待持续计算，不区分作者修改与编辑处理。若以后要分析各环节用时，可另增可选时间记录；本次保持原算法。
2. **退稿后的写作周期。** 当前回到“正在写”并沿用已填写的开始日期。若希望每轮修改单独计时，需要先定义“写作总用时”和“本次修改用时”；本次不重置旧日期。
3. **有进行中投稿时的归档。** 当前允许归档并停止提示，但保留轮次。如果以后希望归档必须先结束投稿，需要另行确认；本次不自动结束、撤稿或转投。
4. **录用与发表。** 继续使用“已录用/发表”合并阶段，刊出信息仍记在备注。需要成果统计时再讨论可选刊出字段。

## 技术栈建议

当前功能规模适合现有标准库与原生页面，不需要 React、额外组件库或服务器。新设计复用现有侧栏、确认框、表格、图标、接口和 SQLite 表结构，没有增加云端上传或联网依赖。未来只有在多人共享、云同步或远程访问需求明确后，再评估技术栈调整。

## 验证与交付

61 项 Python 测试与 28 项页面逻辑检查通过。新增验证覆盖非 schema 版本升级备份、重复启动、备份失败、普通编辑/删除/恢复不备份、请求重试，以及 0/1/3/4/5/8 份备份的显示边界。

真实浏览器已操作独立演示数据：新建已投稿论文、文件路径关联、修改进展、实际转投、删除演示记录、期刊 URL 错误修正、备份展开/收起。新增论文使备份增加一份，随后的进展、转投和删除未增加备份。

已检查正常窗口、726px 窄窗口及 390px 手机宽度，修正了手机导航字样换行，实际测量最小字号 16px、页面无整体横向溢出，宽表仍在容器内滚动，表单键盘焦点保留在侧栏。

本机系统文件选择器返回值、取消及侧栏切换后的处理由独立前端测试验证，浏览器自动化无法直接操作 Windows 系统窗口；实际页面已验证路径关联与保存，不宣称已自动目视验收系统对话框。
