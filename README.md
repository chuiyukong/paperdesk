# PaperDesk · 论文管理台

一个在 Windows 本机运行的论文投稿管理工具。浏览器提供界面，Python 和 SQLite 自动保存记录，无需购买服务器或安装第三方依赖。

![海军蓝界面预览](界面预览.png)

## 开始使用

1. 安装 **Python 3.12**，保留 Python Launcher 和 Tk 组件。
2. 下载 [最新版本](https://github.com/chuiyukong/paperdesk/releases/latest) 的 ZIP，解压到一个固定文件夹。
3. 双击 **启动论文管理平台.cmd**，浏览器自动打开平台。

可运行 **create_desktop_shortcut.py** 创建带平台 Logo 的“论文管理台”桌面快捷方式；使用 Python 无窗口启动，重复启动复用已有服务。移动程序目录后重新创建即可。

默认优先使用 `http://127.0.0.1:8766/`。端口被占用时自动选择后续可用端口；重复启动复用已有服务。访问网址只会打开页面，启动程序需要双击入口。

## 功能

- 六种阶段：计划中、正在写、已投稿、退修中、已录用/发表、归档。
- 计划中、正在写可记录初始目标期刊，独立于实际投稿期刊和转投候选。
- 分别记录计划建立日期、开始撰写日期，并显示对应阶段的天数。
- 每篇论文有唯一稿件编号，新建时自动建议下一位，可修改；首页显示并支持编号搜索。
- 每轮投稿分别记录期刊、日期、期刊稿号、反馈、结果和等待天数；旧期刊稿号继续保留并可搜索。
- 登记实际转投时，一次结束旧轮次并创建新轮次，保留曾投期刊、原记录与候选顺序。
- 已经投出的论文可直接以“已投稿”或“退修中”添加，同时登记原投稿期刊与日期。
- 按等待天数或具体日期安排转投，保存有序候选期刊；只显示超期提示。
- 管理期刊投稿入口，关联并打开本地稿件及文件夹。
- 独立保存期刊投稿须知链接，从期刊管理直接打开作者指南。
- 新建时沿用当前阶段与最近作者；投稿记录保留单一的主要操作入口。
- 标题、作者、标签搜索，阶段与期刊筛选，按日期或等待天数排序。
- 仅新增论文后与升级前自动备份，保留手动完整备份及 JSON 导出恢复；备份过多时折叠显示。
- 保存重试去重、多页面修改冲突保护、页面与服务版本检查，以及备份和数据库诊断。
- 参考 Linear 规范的石墨钴蓝工作台；清晰中文排版、分组表单、本地文件关联与六种状态。
- 全界面文字最小 16px，日期使用中文年月日，提供明确的退出按钮。

界面截图使用独立演示记录。首次运行从空白开始，不会扫描已有稿件。

## 保存与升级

数据位于 Windows 当前用户的 `%USERPROFILE%\PaperDesk\`，与程序源码分开。更新时先退出平台，再替换程序文件并重新启动。v1.2.1 统一数据位置，避免打包应用与资源管理器启动时分别读取不同的 LocalAppData 数据库。首次启动会查找旧版 PaperDesk 数据库，将唯一一组非空记录校验后迁入，并保留原数据库和旧备份；多份内容不同的非空数据库会提示核对，不会自动覆盖。

备份列表显示每份快照的论文、期刊与投稿数量。恢复前先校验并预览，完成后显示恢复数量；恢复空备份会明确提示。仍支持第一版 JSON 和本机快照，旧记录未填写的新字段保持为空。

v1.3.0 升级前保留快照，并为原论文生成唯一编号。原投稿轮次中的稿号仍保留为期刊稿号。旧页面需刷新后使用；旧服务未退出时，新启动入口会提示退出。

v1.4.0 调整为仅新增论文成功后与升级前自动备份，普通编辑、期刊修改、投稿进展、转投、删除、恢复及重复启动都不会新增自动备份。手动完整备份和 JSON 导出仍可随时使用。总数不超过 4 份时全部显示；超过 4 份时只显示最新 3 份，其余通过“更多备份”展开。折叠不删除文件，原 30 天保留规则继续适用。

删除、恢复前不再自动生成保护备份，需要保留当前状态时可先手动导出。恢复依然先校验并预览数量，损坏备份或事务失败不会覆盖现有记录。数据位置和旧备份兼容保持不变。

公开仓库包含程序、说明、测试与演示截图。真实论文记录、稿件、数据库和运行日志不纳入版本控制。

详细操作见 [使用说明](使用说明.md)，版本变化见 [更新记录](CHANGELOG.md)，验证结果见 [功能验证](功能验证.md)。界面约定见 [DESIGN.md](DESIGN.md)，全流程发现与业务建议见 [体验审查与改进](docs/体验审查与改进.md)。

## 开发与验证

Python 3.12 标准库即可运行：

```text
py -3.12 -B -m unittest -v test_paperdesk
node --check web/app.js
node test_frontend.js
py -3.12 paperdesk.py --no-browser
```

也可通过 `--data-dir` 指定独立测试数据目录，通过 `--port` 指定测试端口。GitHub Actions 会在 Windows 上执行自动测试。运行程序不需要 Node.js；Node.js 仅用于开发时的页面逻辑检查。
